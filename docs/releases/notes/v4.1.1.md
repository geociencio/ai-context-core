# Release Notes - v4.1.1 (Report Correctness Fixes)

This is a **patch release** that fixes five report-correctness defects found while
adopting `ai-context-core` 4.1.0 in an external QGIS plugin. No public API
changed.

## Highlights

### 🔒 Analysis cache is now versioned
- The cache (`.ai_context_cache.json`) stores a `_meta` block with the cache
  `schema`, the analyzer `version`, and a fingerprint of the effective config.
  Any mismatch discards the cache, so upgrading `ai-ctx` or editing the config
  can no longer replay stale AST results. This removes the need for a manual
  `ai-ctx clean` after every upgrade.

### 🛡️ Real security severity
- `PROJECT_SUMMARY.md` now reports the **actual** highest severity of a module's
  findings instead of always showing `HIGH`. The severity is recomputed both for
  AST-only modules and when AST issues are merged into a module that already has
  secrets. The security section also appends `… (+N more modules)` when more than
  three modules are affected.

### 🔗 Intentional re-exports are no longer "unused"
- Names declared in `__all__` are treated as used, and package `__init__.py`
  files are exempt from unused-import reporting by default. Toggle with
  `[patterns.unused_imports].ignore_package_reexports = false`.

### 📈 Code-scoped churn
- Git churn now excludes paths outside the analysis scope (documentation, build
  artifacts, …). The original git-wide total is kept as an "all tracked"
  reference in `ai-ctx git` and `AI_CONTEXT.md`.

### 🧭 Conditional QGIS Processing note
- The "No Processing Algorithms found" recommendation is now shown only when the
  plugin actually imports the Processing framework (without defining algorithms).
  Plugins with no processing intent no longer receive the advice.
